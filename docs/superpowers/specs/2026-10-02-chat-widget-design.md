# RAG_AGENT 聊天浮窗设计

## 目标

为现有 RAG_AGENT 增加一个可直接通过公网体验的聊天浮窗。老板打开 FastAPI/ngrok 根地址后，看到右下角 AI 按钮，点击后在对话框中提问并实时看到回答。

## 范围与约束

- 保留现有 `/api/assistant/chat`、`/health` 和 `/docs` 接口行为。
- 前端独立放在 `frontend/`，使用原生 HTML、CSS、JavaScript，不新增构建工具或运行时依赖。
- 前端和 FastAPI 使用同源相对路径，公网隧道只需要暴露 8000 端口。
- 支持 SSE 流式输出、发送中状态、错误提示和清空当前对话。
- 本次不实现账号体系、持久化会话、文件上传或后台管理。

## 结构与数据流

1. FastAPI 在现有 API 路由之后挂载 `frontend/` 静态目录，根路径返回 `index.html`。
2. 页面初始只显示右下角浮动按钮；点击按钮后展开聊天面板，再次点击可收起。
3. 用户提交问题后，浏览器向相对路径 `/api/assistant/chat` 发送 JSON，请求 `stream: true`。
4. 浏览器读取 `text/event-stream`，解析 `intent`、`token`、`done` 和 `error` 事件，逐字更新助手消息。
5. `done` 或 `[DONE]` 到达后结束加载状态；网络错误或服务端 `error` 事件显示可读提示。

## 视觉与交互

- 深色背景、紫色强调色，与 WillBet AI 的现有视觉保持一致。
- 浮窗固定在右下角，桌面端为窄面板，窄屏幕自动占满可用宽度。
- 用户消息靠右，助手消息靠左；输入框支持 Enter 发送、Shift+Enter 换行。
- 关闭浮窗不删除已显示内容；“清空”按钮只清除当前浏览器内存中的消息。

## 验证标准

- `GET /` 返回前端页面，`GET /health` 仍返回 `{"status":"ok"}`。
- 现有自动化测试全部通过，并新增静态页面路由检查。
- 使用现有 ngrok Basic Auth 链接打开根地址可以显示浮窗；发送测试问题能看到流式回答或明确错误提示。

## 非目标

- 不重写 RAG 检索、意图路由、Mock 平台适配器或 DeepSeek 调用。
- 不把 API Key 放进前端代码。
- 不把聊天记录写入服务端或 Git。
